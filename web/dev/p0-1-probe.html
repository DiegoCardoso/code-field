P0-1 probe: 1Password on Chrome

This page measures the 1Password badge and its one-time-code fill (PLAN.md P0-1, SPEC §11.6 and §7.5). The page logs events and badge geometry automatically. You fill in the rest in Record, then copy it as Markdown. Use the Base theme unless a step says otherwise.

Steps

  1. In 1Password, create a Login item named code-field probe. Set the website to this page's origin, the username to probe, and any password.
  2. In that item, add a One-Time Password field with the secret JBSWY3DPEHPK3PXP. This is a public test secret, not a real account.
  3. Press Reset the run under the targets, so nothing from an earlier visit in this tab is kept. Leave the 1Password extension unlocked and keep autofill on.
  4. Badge. Focus each field in Targets, one at a time. For each badge that appears, read its entry in Badges: its size and its offsets from the input's and the host's right edges. The log keeps the last geometry it saw, so the badge can disappear when you move on. Step 9 tells which edge it anchors to.
  5. If Badges stays empty or shows a 0×0 size, measure by hand. Point at the badge's top-left corner and press Ctrl+Shift+M. Then point at its bottom-right corner and press it again. Stop the pointer just outside each corner: over an iframe the page sees no pointer moves, and the reading is stale. As a cross-check, Cmd+Shift+4 shows pixel sizes as you drag. If the badge's parent is dc-code-field or probe-shadow-host and its size is 0×0, it is not rendered at all: record that, because it is a finding about the component.
  6. Resize. Press Toggle width under each target, and also resize the window. Record if the badge moves with the input. The badge log notes every move.
  7. Fill. In each target, open the 1Password menu and fill the one-time password. Don't type in the field during the fill. In Events, check that the value arrived, which events fired, and their isTrusted and inputType. The page marks an event FILL when no key or paste came just before it. Only those count in Fill events. A red SILENT line means the value changed with no input event, so SPEC §7.5 needs polling.
  8. Save login. Type a code by hand and blur. Record if 1Password offers to save or update a login. Then add ignore=1 to the URL's query (?ignore=1, or &ignore=1 after ?theme=…), reload, repeat, and record if the offer stops. Also record if fill still works with it on. Use the URL, not Toggle data-1p-ignore, for the answer: 1Password may read the attribute only when it first scans the page.
  9. Clip. Turn Toggle width off first. In Widen and clip, raise the widen value until the readout says the badge clears the last cell. Click into the lab field again after each change, so the badge comes back. Compare the two offsets in the readout as the widen grows: the one that stays constant is the edge the badge anchors to. Then try each clip strategy. For each one, press Fill 123456, click the first cell, then click the last cell. The readout must show [5, 6]. Repeat with Fill 12345: the last click must show [5, 5]. Also click just right of the last cell, in the overhang, and record what the readout says it hit. Uncheck Outline the input, Tab in, and look for a clipped focus ring on the active cell.
  10. Repeat the badge and clip checks once in Lumo and once in Aura, with the switcher at the bottom right. Switching reloads the page. The record and the logs survive the reload, in this tab only, and each log line notes the theme it was taken in.
  11. Fill in Record, press Copy as Markdown, and paste the result into the chat.
